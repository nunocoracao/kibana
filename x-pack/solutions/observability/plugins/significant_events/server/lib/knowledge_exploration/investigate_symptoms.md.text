# Investigate a symptom

Start with enabled sources and their throughput. For source_esql copy the short catalog slug into sourceIds. Results carry canonical source IDs for writes. Identify emitting operations, namespaces and rare services. For each available source, reuse a relevant saved measurement or inspect the actual schema and a few scoped outcomes. Profile candidate columns with fieldSearch (pipe-separated keywords). Copy exact populated names into KEEP; quote a literal dotted name, leave wildcard patterns unquoted. Use first_seen and last_seen for MIN/MAX timestamp aliases. Watch successful-operation latency, partial results, correctness and backlog as well as terminal errors. If telemetry is unavailable, continue on sources that emit.

Bound time and scope before reading. Sample dense exploration, stratify by cohort and use esql_guide for CATEGORIZE, counters and query syntax. LIMIT controls output size. Confirm candidates with short unsampled aggregates. Filter to the same operation and count successes, technical failures, ordinary rejections and unknowns. Group before limiting. For retry or fallback, verify the terminal result for the same logical operation. A caller's error can be an expected downstream decision. Look for an increase in the rejection share or independent evidence of lost work.

Inspect the newest complete minutes individually and compare them with multiple comparable buckets from a healthy period before onset. A long rolling average can hide a new problem; neighboring minutes can both be degraded. Preserve numerator, denominator and scope. If a rare cohort is affected, compare that cohort with itself. If a partial result is customary, measure excess and its effect. Treat missing rows as unknown. For timeouts, delayed completions or drained queues, identify when affected work started. Correlate request IDs or subtract an observed elapsed duration from the completion timestamp using verified units. Compare new attempts and successes after the onset or recovery boundary. Late failures of earlier attempts can explain a past episode without indicating fresh impact. Before finishing, follow the strongest credible abnormal observation through to a current verdict. Compare the newly affected minute against like healthy buckets instead of averaging the onset into earlier successes. When caller and callee independently show repeated failed attempts, unknown total ingress limits blast-radius claims and does not erase the observed impact. Report a demonstrated blocked operation immediately. If impact looks ordinary, keep the measurement and continue without opening an incident.
