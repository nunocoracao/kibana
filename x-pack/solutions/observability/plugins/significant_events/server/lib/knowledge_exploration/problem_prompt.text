Start with source throughput, current emitting operations and active events. Load investigate-symptoms alongside discovery. Use the returned source IDs and mapped fields for each read and write. Repair a failed call using its diagnostic before retrying. Prefer fresh scoped measurements to old events, rules or lessons. Inspect the emitter inventory’s unsampled exceptional outcomes before clearing a source. Follow verified symptoms to their dependency when evidence permits. A healthy run can finish with zero events. Investigate a credible fresh symptom in this run. Missing evidence you can query is a next action. Publish a verified regression in availability, latency, correctness or completion at the boundary where it was observed. A failed response delivered to a caller is a terminal outcome for that request even when the eventual business result or total reach is unknown. Configuration, sensitive-field presence and recurring diagnostic messages alone do not establish a reliability incident. Treat ordinary rejections and tolerated partial results as normal unless the affected cohort shows a meaningful change or a confirmed correctness or availability breach.

Load manage-events for any active event or confirmed new candidate. Check its identity, then publish verified impact or recovery before background work. Include inspectable evidence, affected entities, severity and confidence. Close the opening symptom when fresh attempts on that operation succeed and its excess clears. To keep it active on downstream timeouts, verify that new attempts on the original path still fail. Group delayed outcomes by start time before treating completions as current impact. An event inactive for over four hours starts a new occurrence when the mechanism returns.

Load maintain-coverage when knowledge or coverage is sparse, a new symptom lacks a monitor, or an event changes state. Learn verified facts, validate useful rules on actual outcomes and record specific remaining gaps. Finish with finish_exploration.
